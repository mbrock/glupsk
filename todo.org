* Purpose

This file tracks architecture and refactoring work that is valuable but not
necessary to do in the middle of feature work. The bias is toward clearer
boundaries, fewer duplicated VM rules, and keeping backend-specific IO separate
from common Glulx and Glk semantics.

* NEXT Split VM execution helpers out of core/execute.cpp
:PROPERTIES:
:Area: vm
:Value: high
:END:

~core/execute.cpp~ is currently the largest file and mixes several layers of
the interpreter. Keep opcode dispatch there, but extract the helper subsystems
that have their own semantics and tests.

* TODO Create shared opcode metadata
:PROPERTIES:
:Area: decode execute trace
:Value: high
:Suggested_File: core/opcode_meta.hpp core/opcode_meta.cpp
:END:

Opcode facts are currently spread across decode, execute, and tracing logic.
Create one shared source of truth for:

- opcode names
- operand counts
- store operand positions
- special load widths
- trace annotations where they are mechanical

Keep this modest at first. The goal is not to rewrite the interpreter into a
table-driven VM, just to stop duplicated opcode knowledge from drifting.

* Notes

- ~core/machine.*~, ~core/story.*~, and ~core/decode.*~ are currently fairly
  cohesive compared with the execution and Glk runtime files.
- Prefer extracting real conceptual modules over making many tiny files.
- Keep the VM state easy to serialize, but do not force host/runtime helper
  structures to be pointerless when they are not VM state.
- Keep platform-specific IO in hosts; keep common Glulx and Glk semantics in
  reusable runtime code.
